# Optical Manager — المتطلبات الحالية

## الهدف
برنامج Web محلي لمستخدم واحد في محل بصريات، يركز على السرعة: إدخال العميل والقياسات والسعر والدفع، ثم حفظ وطباعة الفاتورة مباشرة.

## الواجهات
- لوحة التحكم: عدد الفواتير، إجمالي المستحق، إجمالي المدفوع، إجمالي المتبقي، وآخر الفواتير.
- فاتورة: واجهة واحدة شاملة بثلاثة أقسام: بيانات العميل، بيانات القياسات، الحساب.
- كشف الحساب: مكون مستقل للعمليات المحفوظة مع عرض يومي/شهري/سنوي، البحث والفلترة حسب حالة الدفع، والتعديل والطباعة والحذف.
- الإعدادات: بيانات المحل، العملة، حجم الطباعة، والنسخ الاحتياطي.

## بيانات الفاتورة
- اسم العميل.
- رقم الجوال.
- تاريخ الفاتورة وتاريخ القياسات.
- OD/RIGHT: SPH, CYL, AXIS, ADD.
- OS/LEFT: SPH, CYL, AXIS, ADD.
- PD وNear PD والفاحص والملاحظات.
- السعر، الخصم، الإجمالي، المدفوع، المتبقي.
- رقم واحد فقط: `invoice_number`.

## غير موجود في الواجهة
- لا توجد صفحة إدارة عملاء.
- لا توجد صفحة إدارة فحوصات.
- لا توجد صفحة مستقلة للفواتير كإدارة؛ كشف الحساب هو سجل الفواتير.
- لا يوجد Prism أو Base.
- لا يوجد رقم فحص مستقل.
- لا يوجد مفهوم منفصل للفحص كعملية تجارية جديدة.

## قاعدة البيانات
SQLite عبر `better-sqlite3` مباشرة. لا يستخدم المشروع Prisma.
الحقول الجديدة لقياسات النظر موجودة داخل جدول `invoices`. جدول `exams` القديم يبقى فقط للتوافق مع قواعد البيانات والنسخ الاحتياطية القديمة، ولا تُنشأ فيه سجلات جديدة.

## الطباعة
الفاتورة المطبوعة تجمع بيانات العميل والقياسات والحساب في نموذج واحد، وتستخدم العملة وحجم الورق الحاليين من الإعدادات.
